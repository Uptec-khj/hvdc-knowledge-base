# P-2026-003 InterOPERA D1.3 다중 벤더 EMT 상호작용 연구 절차

## 문제와 기여

다중 단자·다중 벤더(MTMV) HVDC에서는 여러 공급자의 제어·보호 모델과 계통 모델을 한 환경에 결합해야 한다. 이 보고서는 기존 P2P HVDC·해상 PPM 연결 절차를 확장해 상호작용 연구의 시점, 책임, 모델, 정보 교환과 시험 묶음을 하나의 프로젝트 과정으로 제안한다. 문서 자체는 일반 틀이며 실제 사업의 토폴로지·기능·계약에 맞춘 구체화가 필요하다고 밝힌다(Executive summary; §1.5; §8).

## 대상 시스템과 분석 단위

- 대상: 해상 PPM과 육상 AC 계통을 포함할 수 있는 MTMV VSC-HVDC 계통
- 분석 단위: 개별 장치의 독립 성능이 아니라 여러 서브시스템을 연결했을 때의 시스템 상호작용
- 모델: generic 모델에서 vendor-specific offline EMT, SIL/HIL과 현장 검증 자료로 단계적으로 갱신
- 해석 영역: EMT 시간영역을 기본으로 하되 소신호 안정도에는 주파수영역·상태공간 모델을 함께 사용

정격·토폴로지·운전점은 하나의 고정 벤치마크로 규정하지 않는다. 따라서 이 보고서만으로 서로 다른 프로젝트의 성능 수치를 직접 비교할 수 없다.

## 제안 절차

### 1. 프로젝트 단계와 연구 경계

§1.4는 기본 설계부터 상세 설계, 상호작용 연구·시운전 준비, 시운전, PPM 연계 운전과 시험 운전까지 여섯 단계를 둔다. §1.5는 다음 네 요소를 기존 절차의 확장점으로 제시한다.

1. 새 인터페이스·기능·운전 모드까지 포함하는 연구 범위 확장
2. 책임 주체·적정 모델·판정 기준 검증 절차의 명시
3. 단독 시험으로 확인 가능한 성능과 시스템 전체 상호작용 연구의 분리
4. 이해관계자 사이의 반복 절차와 데이터 교환 요구 명시

### 2. 모델의 적합성, 검증과 벤치마킹

§2.1–2.2는 RMS/phasor-domain, EMT 시간영역, 주파수영역과 상태공간 모델의 용도를 구분한다. 빠른 스위칭·고장·보호·제어 상호작용에는 작은 시간 간격의 EMT 모델이 필요하며, 소신호 연구에는 EMT 스캔, 전달함수·임피던스 또는 상태공간 모델을 사용할 수 있다.

§2.3에서 model validation은 물리·수치·기능적 현실성과 요구 동특성·인수 기준 충족을 확인하는 활동이다. benchmarking은 같은 시스템의 둘 이상의 모델을 서로 다른 플랫폼·환경에서 비교하는 활동이다. 시간영역에서는 step·fault 응답을, 주파수영역에서는 임피던스·어드미턴스·Bode 응답을 비교할 수 있다. 두 활동의 책임은 주로 벤더에 있으나 시스템 통합자도 통합 전 점검을 수행할 수 있다.

### 3. 모델 공유와 반복 갱신

Figure 14와 §3.2는 초기 generic 모델이 상세 설계의 vendor-specific offline 모델, 이후 SIL/HIL 및 현장 자료 기반 모델로 바뀌는 수명주기를 제시한다. 통합 시험에서 예상하지 못한 상호작용이 발견되면 모델·설계·완화책을 갱신하고 재시험한다.

§3.3.1은 모델 공유 계약 또는 NDA에 수신자, 사용 목적, 범위·내용·형식과 사용 조건을 명시하도록 권고한다. 벤더는 지식재산을 보호하기 위해 모델을 적어도 부분적으로 black-box로 제공할 수 있어야 한다. 이 원칙은 공유 자체를 없애는 것이 아니라 통합자가 필요한 입력·출력과 실행 조건을 확보하면서 내부 구현 공개를 제한하는 경계다.

§3.4는 시스템 통합자가 다중 시스템 상호작용 시험 전에 단일 벤더 시험, 납품 완전성·품질, 통신 연결, 실제 전기적 상호작용이 없는 실시간 시뮬레이터 인터페이스, 독립 동특성과 통신 성능을 확인하는 준비 단계를 둔다. 준비 시험 통과가 상호작용 연구 투입의 게이트다.

## RQ-001에 대한 추출 결과

1. 단독 적합성 시험과 시스템 전체 상호작용 연구는 목적과 책임이 다르며, 전자는 후자 투입 전의 품질 게이트로 사용된다. [[40_Evidence/E-2026-001 단독 시험과 시스템 상호작용 연구는 목적을 분리한다|E-2026-001]]
2. 모델 교환은 공개/비공개의 이분법이 아니라 계약으로 용도·수신자·범위·형식·조건을 고정하고 black-box로 내부 구현을 보호하는 경계 설계다. [[40_Evidence/E-2026-002 모델 공유 계약은 사용 경계와 black-box 보호를 정의한다|E-2026-002]]
3. 검증 방법은 EMT 한 종류로 끝나지 않는다. 프로젝트 단계와 현상에 따라 offline EMT, 실시간 SIL/HIL, 주파수영역·상태공간 분석, 시운전 자료가 연결된다.
4. 판정 기준은 프로젝트 기능 요구와 사전에 정의한 acceptance criteria에 의존한다. 보고서는 모든 프로젝트에 적용할 단일 정량 임계값을 제공하지 않는다.

## 한계와 재현성

- V2는 consensus process 준비 판본이다. 이후 합의본·개정본이 공개되면 버전 차이를 재검토해야 한다.
- 절차 제안이 중심이며 모든 패키지에 대해 다중 벤더 현장 결과를 제공하는 성능 입증 보고서가 아니다.
- 기능 요구, 모델·플랫폼 요구 등 다른 InterOPERA 결과물에 의존한다. D1.1·D1.2·D2.1과 대조 전에는 요구의 완전성을 판단하지 않는다.
- 공개 문서로 절차와 입력 항목은 재현할 수 있지만 vendor-specific 모델·계약·NDA·세부 설정은 공개되지 않을 수 있다.
- 이번 검토는 부록의 사례 계산을 재실행하지 않았고 참고문헌의 원출처도 전부 확인하지 않았다.
