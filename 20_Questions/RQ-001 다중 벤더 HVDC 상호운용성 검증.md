# RQ-001 다중 벤더 HVDC 상호운용성 검증

> [!note] 제안된 파일럿 질문
> 연구 창고의 연결 구조를 시험하기 위한 초안이다. 사용자가 세부 주축을 확정하기 전까지 `proposed`를 유지하며 실제 조사·검증이 수행된 것으로 집계하지 않는다.

## 연구 질문

다중 벤더 또는 독립 제어 구현이 결합된 VSC-HVDC 시스템에서 **선택한 제어·보호·시험 인터페이스를 검증하기 위해 어떤 정보 교환 경계, 모델 가정, 시험 시나리오와 판정 지표를 사용하며, 그 결과를 다른 시스템에 전이할 수 있는 조건과 한계는 무엇인가?**

## 1주차 범위 확정 게이트

아래 주축 중 하나만 선택한다. 선택하지 않은 항목은 인접 맥락 또는 후속 질문으로 둔다.

| 선택 | 주축 | 포함할 핵심 결과 | 범위 축소 예시 |
|---|---|---|---|
| [ ] | 제어 상호운용성 | 소신호/과도 안정, 전력·전압·주파수 응답, 제어 상호작용 | 보호 상세는 제어 결과에 영향을 주는 조건만 기록 |
| [ ] | 보호 상호운용성 | 고장 검출·선택·차단·복구와 제어 전환 | 정상상태 제어 성능은 보호 시나리오 초기조건만 기록 |
| [ ] | 인터페이스·시험방법 | 모델·신호·파라미터 교환, black-box 경계, 시험 계층과 판정 | 개별 제어 알고리즘 성능 순위는 제외 |

주축 선택일: `미정`  
선택 이유: `미정`  
12주 종료 시 답하려는 핵심 결과 2~3개: `미정`

## 분석 단위

- 기본 단위: 하나의 고유 연구 또는 공식 기술 결과물
- 같은 연구의 preprint·최종판·정정판: 한 연구로 묶고 대표 버전 지정
- 프로젝트 소개 페이지: 배경 자료이며 검증 결과로 집계하지 않음
- 표준: 적용 판별로 관리하며 준수·인증 결과와 구분

## 포함 기준

원문에서 다음 5개를 모두 확인할 수 있는 자료를 기본 포함 대상으로 한다.

1. 대상이 VSC-HVDC, MMC-HVDC, MTDC 또는 이에 직접 연결되는 시험·모델 인터페이스다.
2. 둘 이상의 실제 벤더, 독립 제어 구현, black-box 모델, 또는 다중 구현을 명시적으로 모사한 조건이 있다.
3. 선택한 주축과 직접 관련된 상호작용 또는 적합성 문제가 있다.
4. 검증 환경과 최소 한 개의 시험 시나리오가 기술되어 있다.
5. 아래 비교 항목 중 최소 하나에 검증 가능한 정보를 제공한다.

실제 벤더명이 익명이어도 역할·경계·독립성이 설명되면 포함할 수 있다. 표준·공식 보고서·프로젝트 결과물은 방법·요건·시험 정의에 직접 기여할 때 포함하되 논문 정독 수량과 분리한다.

## 제외 기준

- HVDC 관련성이 확인되지 않는 일반 전력전자 연구
- 단일 구현 내부 성능만 다루고 상호운용성 또는 인터페이스 함의가 없는 연구
- 다중 단말이지만 모든 변환기와 제어가 동일 구현이며 다중 벤더 조건을 논의하지 않는 연구
- 검증 조건 없이 제품 우수성을 주장하는 홍보·마케팅 자료
- 프로젝트 목표·계획만 소개하고 방법·시험·결과를 제공하지 않는 페이지: 동향 맥락으로 별도 등록 가능
- 질문의 주축과 직접 관련되지 않은 구성요소 상세 설계
- 같은 연구의 중복 버전: 대표 문헌에 연결 후 중복 제외

## 보류 기준

- 원문이 없거나 초록만 접근 가능함
- 다중 벤더/독립 구현 조건이 원문에서 확인되지 않음
- 시험 결과는 있으나 시스템·시나리오·지표 정의가 불완전함
- 프로젝트 결과물의 최종판·부속 문서 관계가 불명확함

보류 문헌에는 필요한 확인 행동과 재검토 조건을 기록한다.

## 직접 비교 가능성 판정

각 문헌 쌍을 다음 중 하나로 표시한다.

- `direct`: 시스템·시나리오·지표 정의와 기준이 같거나 변환 가능
- `conditional`: 핵심 조건 일부가 다르지만 차이를 명시하고 제한적으로 비교 가능
- `narrative`: 정량 직접 비교는 불가하나 방법·실패 모드·정보 경계는 서술 비교 가능
- `not_comparable`: 핵심 정의 또는 검증 범위가 달라 같은 결론에 사용할 수 없음

## 하위 질문

1. 벤더 또는 독립 구현 사이에 공유하는 모델·파라미터·신호와 비공개 경계는 무엇인가?
2. 제어·보호 책임은 어떻게 분할되고 인터페이스 적합성은 어떻게 판정되는가?
3. 정상·교란·AC/DC 고장·통신 지연·한계 동작을 어떤 범위로 시험하는가?
4. 해석·EMT·SIL·HIL·실험·현장 결과 사이의 상관성은 어떻게 확인되는가?
5. 결과를 다른 토폴로지·정격·계통 조건에 적용하려면 어떤 조건이 필요한가?
6. 공개 자료로 재현할 수 있는 최소 사례와 재현을 막는 정보 공백은 무엇인가?

## 완료 조건

- [ ] 선택한 주축과 인접 범위가 기록되어 있다.
- [ ] 포함 문헌의 시스템·인터페이스·검증 환경·시나리오·판정 기준을 공통 표로 정리했다.
- [ ] 문헌 쌍의 비교 가능성을 direct/conditional/narrative/not_comparable로 판정했다.
- [ ] 대표 주장에 근거와 적용 한계를 함께 연결했다.
- [ ] 재현 가능한 후보 또는 재현을 막는 정보 공백을 특정했다.
- [ ] 검색 범위에서 찾지 못함과 연구 부재를 구분했다.
- [ ] 후속 질문 세 개에 필요한 데이터·노력·우선순위·중단 조건을 적었다.
