# 문헌 탐색과 검토 절차

## 1. 질문과 분석 단위를 먼저 고정한다

대상 시스템, 현상, 비교 대상, 성능 지표, 검증 방법을 한 문장에 넣는다. 첫 파일럿 후보는 [RQ-001 다중 벤더 HVDC 상호운용성 검증](../20_Questions/RQ-001%20%EB%8B%A4%EC%A4%91%20%EB%B2%A4%EB%8D%94%20HVDC%20%EC%83%81%ED%98%B8%EC%9A%B4%EC%9A%A9%EC%84%B1%20%EA%B2%80%EC%A6%9D.md)이며 세부 주제 확정 전에는 `proposed`를 유지한다.

검색 전에 다음을 기록한다.

- 분석 단위: 고유 연구, 표준 판, 공식 프로젝트 결과물 등
- 주축: 제어, 보호, 인터페이스·시험방법 중 하나
- 인접 범위: 주축 해석에 필요하지만 직접 결론 대상은 아닌 범위
- 주요 결과: 안정성, 복구, 보호 동작, 인터페이스 적합성, 재현 가능성 중 우선 항목

범위를 바꾸면 날짜, 이유, 기존 결과에 미치는 영향을 남긴다.

## 2. 검색을 재실행할 수 있게 기록한다

[검색식과 출처 지도](%EA%B2%80%EC%83%89%EC%8B%9D%EA%B3%BC%20%EC%B6%9C%EC%B2%98%20%EC%A7%80%EB%8F%84.md)에서 출발해 검색원, 정확한 검색식, 검색 필드, 날짜 범위, 실행 시각, 결과 수를 [검색 실행 기록](../80_Operations/%EA%B2%80%EC%83%89%20%EC%8B%A4%ED%96%89%20%EA%B8%B0%EB%A1%9D.md)에 적는다. 발행일과 검색엔진 수집일은 구분한다.

초기 범위는 2020-01-01~실행일이다. 기반 연구는 연도 제한 없이 별도 검색하고 인용·피인용 추적으로 보완한다. 검색식 변경 전후의 결과를 한 실행처럼 합치지 않는다. 이 절차는 파일럿 문헌 검토이며 체계적 고찰의 포괄성을 주장하지 않는다.

## 3. 중복 제거

1. DOI를 우선 대조한다.
2. DOI가 없으면 정규화한 제목·저자·연도·프로젝트 결과물 번호를 비교한다.
3. preprint, accepted manuscript, 최종판, 정정판의 관계를 기록한다.
4. 같은 연구의 여러 버전은 고유 연구 한 건으로 집계하되 실제 읽은 버전과 인용할 버전을 구분한다.
5. 표준은 판과 개정·정오표를 별도 버전으로 관리하고 적용 판을 명시한다.

## 4. 제목·초록 선별과 원문 판정

제목·초록 단계의 결정은 `후보 포함`, `후보 제외`, `원문 판정 필요`로 기록한다. 최종 포함은 원문에서 아래 기준을 확인한 뒤 정한다.

### 포함 기준

1. 대상이 VSC-HVDC, MMC-HVDC, MTDC 또는 질문과 직접 연결되는 시험·모델 인터페이스다.
2. 두 개 이상의 벤더, 독립 제어 구현, 비공개 내부 모델 간 상호작용, 또는 이를 모사하는 명시적 다중 구현 조건이 있다.
3. 제어·보호·모델/신호 인터페이스 중 선택한 주축과 직접 관련된다.
4. 검증 환경과 최소 한 개의 시나리오가 기술되어 있다.
5. 질문의 비교 항목 중 최소 하나를 원문에서 추출할 수 있다.

실제 벤더명을 비공개한 연구도 다중 구현 조건과 인터페이스가 명확하면 포함할 수 있다. 공식 프로젝트 결과물·표준·기관 보고서는 질문의 방법·요건·검증 맥락에 직접 기여할 때 포함하되 논문 정독 수량과 분리한다.

### 제외 기준

- HVDC 연계가 확인되지 않는 일반 전력전자 연구
- 단일 구현의 내부 제어 성능만 다루고 상호운용성 또는 인터페이스 함의가 없는 연구
- 검증 조건 없이 제품 성능을 주장하는 마케팅 자료
- 프로젝트 계획·보도자료만 있고 질문의 결과나 방법을 제공하지 않는 자료: 동향 맥락 자료로는 별도 등록 가능
- 같은 연구의 중복 버전: 대표 버전에 연결하고 중복 제외
- 질문의 주축과 무관한 구성요소 상세 설계

### 보류 기준

- 원문 미확보 또는 접근 범위가 초록에 한정됨
- 다중 벤더/다중 구현 조건이 원문에서 확인되지 않음
- 프로젝트 결과물의 최종 버전·부속 문서 관계가 불명확함
- 비교에 필요한 단위·기준·시나리오 정의가 불완전함

보류는 제외로 집계하지 않으며 필요한 확인 행동과 재검토 날짜를 적는다.

## 5. 원문 정독

[TPL 논문 검토](../90_Templates/TPL%20%EB%85%BC%EB%AC%B8%20%EA%B2%80%ED%86%A0.md)에 다음을 적는다.

- 문제와 기존 방법의 한계
- 기여와 분석 단위
- 시스템 토폴로지·정격·운전점
- 벤더/제어 구현 수와 역할
- 공개·비공개 경계, 교환 모델·파라미터·신호
- 제어·보호 책임 경계와 조정 방식
- 검증 환경, 모델 상세도, 시간 스텝, 실시간 여부
- 정상·교란·AC/DC 고장·통신·운영 시나리오
- 지표 정의, 기준값, 비교 대상, 결과와 원문 위치
- 저자 주장, 관찰 결과, 내 해석
- 한계, 재현 자료, 이해상충 또는 참여기관 맥락

HVDC 수치는 전압 정의(극-대지/극간), 용량 기준(극/링크), 주파수·시간 단위, pu 기준을 함께 확인한다. SCR 등 지표는 원문의 정의·계통 구성을 기록하고 다른 정의의 결과를 바로 합치지 않는다.

## 6. 근거 추출

핵심 주장 한 개를 [TPL 근거 카드](../90_Templates/TPL%20%EA%B7%BC%EA%B1%B0%20%EC%B9%B4%EB%93%9C.md) 한 장에 기록한다. 저자의 주장, 관찰 결과, 내 해석을 구분한다. 원문 노트, 페이지·절·그림·표, 적용 조건, 반례 또는 한계를 포함한다. 웹 자료는 절 제목·URL·확인일과 확인 범위를 쓴다.

한 논문에서 추출할 핵심 근거가 없으면 카드를 억지로 만들지 않고 논문 노트에 사유를 남긴다. 수치와 조건을 원문과 대조하기 전에는 `checked`로 바꾸지 않는다.

## 7. 비교 가능성 판정

두 연구의 수치를 직접 비교하기 전에 다음을 확인한다.

| 항목 | 직접 비교 조건 |
|---|---|
| 시스템 | 토폴로지·단자 수·정격·운전점 차이가 해석 가능함 |
| 구현 | 벤더/제어 역할과 공개·비공개 경계가 대응됨 |
| 모델 | EMT/RMS/실시간 모델 상세도와 시간 스텝 차이가 설명됨 |
| 시나리오 | 사건 위치·크기·지속시간·초기조건이 대응됨 |
| 지표 | 정의·단위·pu 기준·측정 창이 같거나 변환 가능함 |
| 판정 기준 | 안정/실패/적합의 임계값과 근거가 대응됨 |

모두 충족하면 직접 비교, 일부만 충족하면 조건부 비교, 핵심 정의가 다르면 서술 비교 또는 비교 불가로 표시한다.

## 8. 종합과 연구 공백

논문 두 편 이상이 모이면 [TPL 종합 노트](../90_Templates/TPL%20%EC%A2%85%ED%95%A9%20%EB%85%B8%ED%8A%B8.md)를 사용한다. 종합 문장의 각 결론에는 근거 링크를 붙인다. “검색 범위에서 찾지 못함”, “자료 비공개로 확인 불가”, “연구가 존재하지 않음”을 구분한다. 후속 질문에는 필요한 데이터·판정 기준·예상 노력·중단 조건을 적는다.

## 9. 검토와 재방문

검토 완료 시 `status`, `updated`, `last_verified`와 등록부를 갱신한다. 개인 운영자 1인이 상태를 바꿀 때는 완료 체크리스트와 확인 범위를 커밋 또는 운영 기록에 남긴다. 새로운 반례·정정·후속 연구가 나오면 기존 결론을 수정하고 이유를 남긴다.
